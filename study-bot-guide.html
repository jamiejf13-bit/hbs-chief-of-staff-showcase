Automating HBS · full guide

Build a daily study bot for HBS

One scheduled task, running on your laptop every weekday after class. It files what your professors post to Canvas, writes study notes for tomorrow's cases, keeps a participation log honest, and scans recruiting, then sends you one message. This is the full build, in the order it has to happen, including the mistakes that cost the most time to find.

A study partner, not a substitute. Read the case and form your own view first; use the notes to check your thinking. The bot never writes anything you submit. Read each course's AI policy before you start and follow it: some permit AI on problem sets and bar it on exams, and some assignment instructions bar help from classmates and TFs without mentioning AI. Read the policy rather than guessing in either direction.

Tip: you can open Claude in Chrome on this page and ask it to walk you through, or do, each step. It checks with you before anything important.

What you get

One task fires on weekdays shortly after your last class and does four jobs in a single run. Everything it produces lands in one folder, and it pings your phone once.

PartWhat it producesWhat it needs from you
Canvas filingEvery file posted since yesterday, downloaded and filed in the right course folder, with post-class slides quoted into a running notes doc per courseNothing, once set up
Study notesFor each of tomorrow's cases: the assignment questions word for word, key figures with the exhibit cited, arithmetic worked step by step, and the strongest argument on each sideReading the case yourself; correcting the format for the first few weeks
Participation logA row per class with what you said and how it landed, plus a dashboard of where you've gone quietA one-line note after class
Recruiting scanNew events matching your focus, written to a watchlist, with deadlines inside three days flaggedStaying signed in to 12Twenty

Two design decisions matter more than anything else.

  • One scheduled task, not six. Every scheduled task opens a fresh conversation each time it runs, so six daily tasks means six new conversations a day. That volume is what makes people switch the whole thing off. Build one task that does everything, with one notification.
  • State lives in files, never in a conversation. Every run starts with no memory of the last one. Your tracker and a context file are the only continuity, so anything the next run should know has to be written to disk.

Before you start

  • The Claude desktop app, on the laptop where your school files live, on a plan that includes scheduled tasks. The laptop has to be awake, with the app open, when the task runs.
  • The Claude in Chrome extension. Canvas and 12Twenty sit behind university sign-on, and the extension acts in your real, signed-in Chrome. There's no Canvas API key a student can get on their own, so the browser is the route.
  • One cloud-synced folder for school files (OneDrive, iCloud Drive or Dropbox), so files reach your phone. Exactly one copy.
  • Under 15 minutes to set up, then a few small corrections over the first weeks as you tune the notes to how you study.

Two things to know first: a long run occasionally loses its connection partway and needs a retry, and the system only sees what your professors actually post. Some post everything; some post very little.

1Build the folder structure

Pick one root folder and never use a second. Build this by hand before involving Claude; the task will follow it exactly and won't reorganize it.

HBS\
  00 Start Here\            Claude Context.md
  01 Master Tracker\        Master Tracker.xlsx
  02 Courses\
    <COURSE>\
      Admin\
      Class Material\       one subfolder per case
      Core Curriculum Readings\
      Wrap Slides\          every post-class deck for the course, flat
      <COURSE> - Running Class Notes.docx
  03 Section\
  04 Takeaways Digests\
  05 Recruiting\
  • All wrap slides for a course go in one flat folder, not inside each case folder. When you revise for a midterm you want every takeaway deck in one place, in order.
  • Case materials go in Class Material\<Case>\: the case PDF, exhibits, your study notes, your own notes. One folder per case.

The expensive mistake is two copies. If you start in Google Drive and later move to OneDrive, delete or rename the old folder the same day. A task reading one copy while you write to the other will drift apart silently for weeks.

2Build the participation tracker

One spreadsheet in 01 Master Tracker. Ask Claude to build it, then check the column order by hand, because later instructions refer to these columns by name.

Class Log tab

Columns, in this order: Date | Course | Case / Topic | Prepped | Spoke | Contribution Type | Impact (1-3) | What I said | Key takeaway | Concepts / Frameworks | Follow-ups | Cold-called | Question I still have

Add dropdown validation with exactly these values, because the task writes these strings and a mismatch silently breaks the dashboard:

  • Prepped, Spoke, Cold-called: Y, N
  • Impact: 1, 2, 3
  • Contribution Type: Opened the case, Built on someone, Countered a view, Analysis/numbers, Reframed the question, Personal experience, Closed/synthesized, Did not speak

The contribution types are the most useful part. They show you whether you've been making the same kind of comment all semester. People from banking or consulting often find most of their comments are Analysis/numbers, while professors tend to reward countering a view and synthesizing what others said.

Keep What I said and Key takeaway as separate columns: one is your contribution, the other is what you learned.

Other tabs

  • Takeaways Index: Date | Course | Concept | In one line | When it applies | Source case | Exam-worthy | Recruiting story?. Flag the last column whenever a concept would make a good interview answer for the roles you want.
  • Assignments: Course | Assignment | Type | Assigned | Due | Est. hours | Status | Priority | Days left | Notes, with Days left as a formula. Fill it once from Canvas and reconcile it monthly.
  • Weekly Review: sessions, times spoke, courses you didn't speak in, what worked, what to fix, focus for next week. Let the task fill everything except what worked and what to fix; those two are yours.
  • Dashboard: per course, sessions logged, times spoke, last spoke, and sessions since you last spoke. Use sessions, not calendar days: a goal like "speak every two or three classes" is counted in sessions, and a course that hasn't met for a week shouldn't look urgent.

Participation expectations differ by course. Many want you to contribute regularly but not every class, so others get a chance. The dashboard is for pacing yourself, not for speaking as often as possible.

3One running notes doc per course

One Word file per course at 02 Courses\<COURSE>\<COURSE> - Running Class Notes.docx. The spreadsheet holds the structured half; this holds the narrative half.

  • One Entries heading at the top, newest entry first, each dated YYYY-MM-DD — Class N: <Case>.
  • Your own notes go first, under My notes. Official content goes below, under From Canvas, quoting the wrap slides.
  • Tell the task in writing that it never overwrites what you wrote. The gap between what you took from a class and what the professor said it was about is the most useful thing in the doc.

Two technical notes worth writing into your context file now. Have the task check for a duplicate Entries heading and merge before adding. And if Word headings fail with KeyError: no style with name 'Heading 2', the fix is to copy an existing paragraph of the right style and change its text, rather than adding a new one by style name.

4Connect your laptop and browser

The laptop

  1. Install the Claude desktop app on the machine with your school folder and sign in.
  2. Give it access to two folders only: your school root and your Downloads folder. Downloads matters because browser downloads land there and the task has to pick them up.
  3. Leave file deletion off. Tell the task in its context file to move anything it wants removed into a _to_delete folder and report it, because a scheduled run has nobody to answer a permission prompt.

The browser

  1. Install Claude in Chrome and allow it on hbs.instructure.com and 12Twenty.
  2. Sign in to both in that Chrome profile and stay signed in.
  3. Move any exported password file off the laptop. The extension can see your browser and your Downloads folder. Name any file it must never read in the context file.

5Find where each professor posts

Open each course in Canvas and copy the number in the URL: …/courses/12345 means the course ID is 12345. Put every ID in the context file.

The task uses these Canvas endpoints, called from a signed-in tab (replace <id> with a course ID):

/api/v1/courses/<id>/files?per_page=100&sort=created_at&order=desc
/api/v1/courses/<id>/files/<file_id>/download?download_frd=1
/api/v1/courses/<id>/assignments?per_page=100
/api/v1/courses/<id>/pages?per_page=100&sort=updated_at&order=desc

Then spend 20 minutes checking where each course actually posts. This is the step people skip, and it costs the most. A scan that only looks at files posted in the last day misses three whole categories:

  • Course Pages instead of Files. Some courses post wraps, problem sets and solutions on Canvas Pages, which the Files list doesn't show.
  • Attachments on the assignment. Some attach the post-class deck to the class's own assignment page.
  • Bulk uploads before term. Some upload a whole term's summaries in one go before classes start. A one-day window never sees them.

Write the general rule into your context file: when a course's notes look thin, compare that course's entire Canvas file list against what's on disk, rather than assuming the course posts nothing.

If your cases come through Harvard Business Publishing, the assignment page carries a coursepack link. Opened in your signed-in Chrome, it leads to the case PDF, which the task can save and read. Expect a few cases to fail where the PDF is scanned images.

6Write the context file

Create 00 Start Here\Claude Context.md. This is the most valuable file in the system: every run reads it first, and anything in it overrides the task prompt. Without it, every run rediscovers the same things and repeats the same mistakes.

Sections to include:

  • Who and what: your section, your courses, when classes end, what you're recruiting for.
  • Where everything lives: the folder layout, and a line naming any old copy to ignore.
  • Tracker schema: the exact columns and dropdown values.
  • Running notes convention: the heading rules and the Word workaround.
  • The skills: what each is for (step 7).
  • Study notes format: this becomes the longest section over time.
  • Course AI policies: what each course permits.
  • Canvas: course IDs, endpoints, and where each professor posts.
  • Recruiting: your filter, and the rule that it never registers you for anything.
  • Gotchas: every problem you hit, written down the day you hit it.
  • Current state: what's been logged and backfilled, open items.

The habit that makes this work: when you correct the agent, write the correction into this file in the same session, with the date. A correction left in a chat is gone when the chat ends, and dated entries let a fresh run tell which rule is current when two seem to conflict.

7Create the two skills

A skill is a folder with a SKILL.md file of instructions Claude loads when a task matches. Ask Claude to write each one and save it. Keep the method in the skills and the task prompt short; when you want to change how notes are written, edit the skill, not the prompt.

Skill one: pull from Canvas

This one does no analysis. It fetches an assignment and its materials, and it reports what it couldn't get rather than filling gaps.

---
name: canvas-pull
description: Pull an HBS assignment, its questions word for word, and its materials from Canvas for a given course and date.
---
1. Find the assignment for the course and date. Class assignments are usually titled "Class N: <Case>" and are due at class start, so today's may have moved to Past Assignments.
2. Capture, word for word: the case title, the framing paragraph, every assignment question in order, any notes on calculations, and the full materials list.
3. Download the materials in batches of fewer than ten and save them to the case folder.
4. Report what was found and, explicitly, what could not be retrieved.

Rules
- Quote questions exactly. Never paraphrase, and never reconstruct them from memory of a similar case.
- If the assignment isn't posted, say so and stop. Never substitute another assignment.
- List every exhibit or file that couldn't be opened, so the notes don't treat it as missing information.

Skill two: study notes

This one runs the first skill, then writes the notes. Start it with this structure and let your own corrections reshape it.

---
name: study-notes
description: Write study notes for an HBS case, for checking my own reading after I've prepared. Never a substitute for reading the case.
---
Structure
1. Title, and the case in one line: the decision and who is deciding.
2. Key terms the session runs on, one line each.
3. Each assignment question, word for word and in order. Under each:
   - the facts and figures the question turns on, each with its page or exhibit cited
   - any arithmetic, one step per line, every number cited, with a plain sentence first saying why the calculation is being run
   - the strongest argument on each side
4. Questions to bring to class.

Rules
- These are notes to check my thinking. Never write anything I would submit, and follow the course's AI policy.
- Every sentence carries a fact. Cut commentary, restatement and flourish.
- If a stated figure can't be reproduced from the numbers beside it, the arithmetic wins: flag it.
- A file that couldn't be opened is not a number the case doesn't state. Name the missing input; never assume a value.

8Create the one scheduled task

In the Claude desktop app, start a new chat, paste the prompt below with your details filled in, and ask: "Schedule this to run on this computer every weekday at 1:00 pm." Pick a time about 30 minutes after your last class. If your schedule is set in UTC, it shifts by an hour when daylight saving ends.

Task prompt
You are my HBS study assistant. This runs every weekday after my last class.
FIRST read [ROOT]\00 Start Here\Claude Context.md. Anything in it overrides this prompt.
Work only inside [ROOT]. Never delete files: move anything to remove into a _to_delete folder and tell me. If my files can't be reached, say so in one line and stop; retry once at most.

1. CANVAS. If Canvas asks me to sign in, stop and tell me. Open a fresh Chrome tab. For each course in the context file, find files created in the last 26 hours, and also check course Pages and the assignment pages for post-class attachments. Download in batches of fewer than ten and file each in the right folder. Add each wrap to the course's running notes doc as a dated entry under From Canvas, quoting the slides. Add genuinely new concepts to the Takeaways Index.

2. TODAY'S LOG. Check the Class Log against today's classes. If I had class and there's no row, ask me in ONE line what I said. Never invent entries. If I stayed quiet, log the row with Spoke = N, or the dashboard will flatter me. My read of how a comment landed overrides yours.

3. TOMORROW'S CASES. For each of tomorrow's classes, use the study-notes skill. Follow the skill; don't improvise the format. If tomorrow's assignment isn't posted, say so and skip that course; never substitute the previous session's case. Name the one class to aim to speak in tomorrow, using the dashboard and my goal for each course, and say plainly if my contribution types are skewing one way.

4. RECRUITING. Check 12Twenty for new events matching: [YOUR FOCUS]. Don't flag: [YOUR EXCLUSIONS]. Update 05 Recruiting\Watchlist.md and report only what's new plus any registration deadline within 3 days. Never register me for anything; that needs my go-ahead for each event, every time.

5. FRIDAYS ONLY. Add a Weekly Review row: classes, times I spoke, courses I didn't speak in, contribution-type mix, and one target for next week. Leave "what worked" and "what to fix" blank for me.

6. FIRST RUN OF EACH MONTH. Write a takeaways digest: concepts grouped by theme rather than course, where courses contradict each other, the five most likely to appear on a final, and which courses look thin, saying whether that's the course or the logging.

FINISH with ONE push message under 150 words: the notes written and for which cases, tomorrow's target class, anything new in recruiting, and the single thing you need from me. Bullets, complete sentences. If nothing happened and nothing is needed, send nothing.

Three lines are load-bearing; don't cut them. "Never invent entries": a made-up log row is worse than a gap, because you'll trust it later. "Log quiet classes": without them every course looks fine. "Never register me": the task runs while you're elsewhere, and anything you can't undo needs you each time.

9Log class in one line

The task handles everything that can happen without you. The participation log can't, because only you know what you said and how it landed.

Keep one ongoing chat for this and message it right after class. A messy sentence is the whole input: "spoke in STRAT about demand vs capacity, what would you have to believe, landed ok." Claude turns it into a Class Log row, a Takeaways Index entry where it earns one, and an entry in the course notes doc.

  • Your read overrides Claude's. If you say a comment was thin, it scores down. You were in the room.
  • One chat, not one per class. Fewer places to check is what keeps you using it.
  • Silence is data. Classes where you said nothing make the dashboard honest. Let the task backfill them from the Canvas assignment list.
  • Photos of handwritten notes can go to the same chat, to be transcribed into the course doc under their own heading, with illegible words marked unclear rather than guessed.

Things that go wrong

Each of these costs at least an hour the first time. Put them in your context file on day one.

SymptomCauseFix
Every course looks on track when you know you've gone quietClasses you didn't report have no rowBackfill Spoke = N rows from the Canvas assignment list
Dashboard cells show blank in Excel or on your phoneThe spreadsheet library keeps formulas but drops their computed valuesHave Claude recalculate the file (for example through LibreOffice) before saving
Dashboard counts are wrong for no visible reasonDates saved as textWrite dates as real dates, never strings
One course has almost nothing filedIt posts on Pages, in assignment attachments, or uploaded everything before termCompare its whole Canvas file list with what's on disk
Downloads stop partwayChrome throttles past about ten filesBatches under ten, or the course's download-as-zip
Screenshots time out and pages stop respondingAn old browser tab frozeOpen a fresh tab at the start of every run
The run can't reach your filesThe laptop was asleep or the app was closedKeep it awake around the run time; retry once, then stop
The recruiting scan is signed out most days12Twenty's session expires in under a daySign in before the run, or treat the scan as best effort. Never let the agent sign in for you.
Your notes doc has entries in two placesTwo runs each created their own Entries headingTell the task to check for a duplicate and merge first
A number in the notes is confidently wrongAn exhibits file failed to download and a value was assumedThe rule above: a file you couldn't open is not a number the case doesn't state

That last one deserves attention. A missing exhibits spreadsheet can lead the notes to say a figure "isn't stated in the case" and assume one. If the assumed number is wrong, it runs through every calculation and can flip the conclusion. The failure isn't the download; it's reporting an unopened file as an absent fact.

How to iterate

Expect the first few weeks of notes to be too long, too padded, or not in your voice. The fix is a loop, and the loop is the real work.

  • Edit one set of notes by hand, then hand it back. Cut what you wouldn't use, reorder what's in the wrong place, rewrite one section the way you want it. Then give it back and say: "this is the structure; write the spec that produces it into the skill and the context file." Editing by hand beats describing in the abstract.
  • Write every correction down the day you make it, dated, with the reason. When two rules conflict, the dated one wins.
  • Expect to reverse yourself. You'll add a section, use it once, and remove it. That's normal, as long as the removal is written down as clearly as the request was.
  • Length isn't the control; filler is. Asking for "shorter" gets the same padding in fewer words. The rule that works is per sentence: every sentence carries a fact, and anything that comments on the answer instead of giving it gets cut.

Honest limits

  • It doesn't write anything you submit. Graded work stays yours, and course AI policies come first.
  • It can't tell you how a comment landed. It logs what you said and counts the pattern; the judgment is yours.
  • The notes don't replace reading the case. If you haven't read it, a professor will find out in one follow-up question.
  • It only sees what gets posted. A course that posts little gives you a thin folder however good the system is.
  • Reliability is real but not total. Expect roughly one run in five to be partly degraded. Build it so a degraded run says what it couldn't do rather than failing silently.

Start with the tracker and the context file; let the automation come second. The automation is the easy half. The hard half is deciding what's worth tracking, and that only becomes clear after a couple of weeks of logging by hand.
